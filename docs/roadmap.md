# Maintenance roadmap

## First 30 days after release

Keep a reproducible public demo using the fictional furniture collection. Ask a small group of willing furniture exporters, factory staff and wholesale suppliers to run the tool with their own approved files. Invite feedback through GitHub Issues. Ask for the OS, tool version, row count, template, task outcome and an anonymized reproduction when available. Log feedback and regressions in issues with the participant's permission.

Maintain a weekly issue triage. Prioritize import errors, unreadable PDFs, image distortion, incorrect packaging math and failures that block a fresh install. Publish a patch when a fix is verified by the relevant CI and rendered example.

## Months 2–3

Review pilot feedback on setup friction and common spreadsheet formats. Prioritize diagnostics export, reusable branding presets and safer handling of larger catalogs. Add sample cases for manufacturer spec sheets and wholesale line sheets when they can be reproduced with synthetic data. Write a short demo guide that shows the original workflow, time spent by volunteers and any remaining manual steps when those observations exist.

## After regular usage is established

Evaluate additional language packs, embedded CJK fonts, accessible PDF output and deployment hardening for shared instances. Make changes from documented demand and regression tests. Review dependencies monthly and record cross-platform results in release notes.

Track GitHub issues, verified downloads when the host reports them, outside contributions, and opt-in examples from actual users. Download counts describe downloads. For evidence of repeat use, collect dated, consented accounts from people who generated catalogs as part of their work. Keep organization names, images and product data private unless their owners authorize publication.
